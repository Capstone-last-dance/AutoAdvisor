# C-02·C-03 선행 구현 현황 (2026-11-03 갱신)

## 구현 및 검증

- `src/common/guards.py`: 학습 신호일 상한, 홀드아웃 라벨 개봉일과 명시 플래그, `purge_signal_dates(signal_dates, *, trading_days, h, next_segment_first_signal, actual_end_dates=None)`. 실제 종료일이 다음 구간에 걸친 라벨이 하나라도 있으면 신호일 전체를 제거한다(DEC-09 (3) 변경). 사전등록 날짜와 KRX 거래일은 호출자가 전달한다.
- `src/backtest/labels.py`: A가 제공할 가격·지수·유니버스·거래정지·상장폐지 표를 받아 4.6절 라벨을 메모리에서 계산한다. 거래정지로 인한 종료 연기와 결측 건수, 명목·실제 종료일 진단값도 반환한다.
- `src/backtest/accounting.py`: 체결 제한, 매수·매도 비용, 주문 체결, 현금 및 일별 NAV의 공통 함수. 목표 비중을 주문 수량으로 바꾸는 방식은 아직 확정하지 않았다.
- `src/backtest/engine.py`: B의 `ExecutionEngine` 인터페이스에 맞춘 `initial_state`·`run_period` 구현. 다음 거래일 종가 체결, 일별 NAV, 벤치마크 구간 수익, 다음 신호일 관측 비중, M9 청산·재시도, 쿨다운, 거래정지·가격 제한, 상장폐지 평가를 한 함수로 처리한다. 현금 부족 시 매도 후 모든 가능한 매수를 같은 비율로 줄이는 **DEC-18 확정 규칙**을 적용했다. 합성 6거래일 구간 5,000회 측정에서 평균 0.38 ms/호출(단일 종목, 현 로컬 환경)이다. 종목 수·이벤트 수가 다른 실제 데이터 성능은 별도 측정이 필요하다.
- `src/backtest/labels.py`: `publish_labels`가 홀드아웃 가드를 재검사한 뒤 D 공용 `io.write_table("labels")`로 저장한다. 실제 원천 자료로 라벨 파일을 만든 것은 아니다.
- `src/backtest/validation.py`: G0 목표 비중을 B의 `sectors_at`·`check_invariants`로 검사한다. M8 미적용 G7 실행은 호출자가 `m8_mode="off"`를 명시해야 한다.
- `src/backtest/metrics.py`: 6.6절의 CAGR, 연 초과수익, 주간 초과수익, IR, MDD, 회전율, rank IC/HAC, ROC-AUC, lift@10%, 하방·반등 포착률. B-01 `IRFunction` 연결용 `validation_ir`는 미산출 IR을 NaN으로 전달한다.
- `tests/`: 손계산 예제, 홀드아웃 경계, 거래정지·상장폐지, 미체결, 비용 0 동일가중 리밸런싱, 공용 I/O 라벨 왕복, 구간 NAV·이벤트 우선순위·G0 검증. 테스트는 합성 자료만 사용한다. B 재리뷰 반영 후 C 관련·D 공용 I/O 테스트 70개와 하위 테스트 51개가 통과했다.

## 실제 산출물 연결 상태

1. A의 `A02_processed` 최종 전달본에서 `prices`와 일별 `status`가 각각 9,331,430행이고 `(date, ticker)`가 전 행 일치함을 확인했다. `is_halted`는 거래량 0 판정과 전 행 일치하고, `101970`·`036220`의 새 회사 첫날 `listed_days`는 1로 수정됐다. 다만 구회사 폐지 이력은 `delisted`에 없으므로 [이슈 #5](https://github.com/Capstone-last-dance/AutoAdvisor/issues/5)의 처리 결정 전에는 해당 구간을 포함한 C 최종 NAV 판정을 하지 않는다.
2. `configs/prereg.yaml`의 공식 확정값. 현재 개발 초안의 날짜·기간·비용을 실험 결과 확정값으로 간주하지 않는다.
3. 현금 부족 시 매도 우선·매수 동일 배율 축소는 DEC-18로 확정됐다. 엔진의 `execute_orders`는 수량 기준 순수 함수이며 현금 초과를 오류로 처리한다.
4. 거래 재개 지연 라벨의 실제 종료일을 반영한 신호일 전체 purge는 DEC-09 (3) 변경으로 확정됐다. A·B·C는 공용 함수가 돌려준 같은 신호일 집합을 사용해야 한다.
5. A의 실제 가격·거래정지·상장폐지 표에서 평가 가격 공백을 처리하는 규칙은 DEC-25 대기다. 현재 엔진은 거래정지일에도 평가 가능한 수정종가를 요구하며 상장폐지일은 명시적 최종 가격을 받는다.
6. B의 RL 환경과 버퍼 백테스트에 실제 엔진을 연결하는 B-05 작업. C 인터페이스 구현과 합성 검증은 끝났으나 B 연결·동일 입력 결과 검증은 아직이다.
7. M9 경보의 실제 `available_at`·청산·쿨다운 출력, 업종 원천 및 사전등록 계약. `investor_flows`는 DEC-22에 따라 제외하고 C-04의 G2는 거래량 비율 대체 정의를 사용한다. 현재 엔진은 적용 거래일별 이벤트 집합을 주입받는다.

## A·D 공용 스키마 확인

- 최종 전달본의 `index.parquet`(KOSPI200)과 `index_kosdaq.parquet`(KOSDAQ150)은 각각 4,141거래일이다. C의 초과수익·벤치마크는 KOSPI200만 쓴다. A PR #1의 공용 I/O 수정본에서는 두 코드가 허용되지만 현재 main의 I/O는 KOSPI200만 허용한다.
- 최종 `status`는 DEC-24의 4열(`date,ticker,is_admin,is_halted`)·일별 자료이며 `is_admin`은 전 행 결측이다. A PR #1의 nullable 스키마 변경이 병합되어야 공용 I/O 검증·저장이 가능하다. `is_halted`의 가격 행 정합성과 거래량 0 판정은 C가 전수 확인했다.
- `index`(KOSPI200), `tickers`, `universe`, `delisted`, `sector`는 현행 공용 검증을 통과했다. `sector`는 3,697종목 중 1,043종목이 '미분류'다. `universe`의 관리종목 제외 단계는 DEC-24에 따라 v1 스텁이며 성과 판정에 사용할 때 그 한계를 기록한다.

## B PR #8 리뷰 반영

- 보유하지 않은 종목의 과거 폐지 때문에 구간 함수가 중단되는 오류를 수정했다. 보유 종목이 폐지된 다음 구간도 계속 실행한다.
- 거래정지로 매도하지 못한 보유분은 재개 첫날 최근 목표 비중을 넘는 부분만 다시 매도한다. 정지로 막힌 매수는 재시도하지 않는다. B가 동의한 해석이며 PM 결정 기록은 대기다.
- 재개일 현재 비중이 이미 축소 목표보다 낮아졌다면 그 종목을 다시 매수하지 않는다. B의 2026-11-03 재리뷰 반례를 회귀 테스트로 고정했다.
- 상·하한가 경계 판정은 공용 `blocked_reason`을 사용한다. 상장 전·폐지 후의 가격·상태 결측은 허용하고 보유·목표 종목에 필요한 당일 값만 검사한다.
- `delistings` 입력 날짜는 정리매매 마지막 가격일이다. A `delist_date`가 그 다음 거래일이면 연결 어댑터가 직전 거래일로 변환한다. DEC-18 매수 배율은 리밸런싱 원장에 기록하고 배율 1 미만 횟수를 엔진에서 집계한다.
- `weekly_active_returns`에는 체결 직전 NAV를 넣고, CAGR 거래일 수는 일간 수익률 개수로 센다. 반등 포착률의 d-1→d 수익에는 d-1 종가 기준 `regime_mc`를 맞춘다. 기본 비용 배율은 1이고 2배 비용 실행에만 2를 지정한다.

위 입력과 결정을 받으면 2025년 신호일까지 라벨 파일을 만들고, 실제 walk-forward NAV와 6.6절 완료 기준의 전체 기간 검증을 진행한다. 2026년 홀드아웃 신호일 라벨은 개봉 조건을 충족할 때까지 생성하지 않는다.
