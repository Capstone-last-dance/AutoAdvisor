# B-09 탐색 실험 기록 (브랜치 `b09-explore`)

이 문서는 브랜치 `b09-explore`에만 있다. 방향과 절차는 main의 `docs/design_B.md` 3.7절을 따른다. 결과는 모두 '탐색'이고 KPI 판정에 쓰지 않는다 (R-15, G7은 R-02도).

## 1. 브랜치 운영
- main에서 갈라졌다 (`fd3e983`, 11/18). main에 병합하지 않고, 필요한 결과만 main 문서로 옮긴다.
- 이 브랜치에서는 코드를 제한 없이 고친다 (B 코드, `configs/prereg.yaml`, 다른 역할 코드 포함). 다만 공용 코드(`src/`)를 고치면 대조 실행(바꾼 것 없음)이 공식 결과를 재현하는지 다시 확인한다.
- 최종 모델은 2021~2025 확인을 거친 변형 중 성능이 가장 좋은 것으로 고른다. 2021~2025를 본 뒤 다시 고친 변형은 '확인 없음'으로 표시한다. forward test나 발표의 운용 모델로 쓰려면 PM 결정(DEC)이 먼저 있어야 한다.
- 11/18 실행분은 스크래치에서 시작했고 같은 날 이 브랜치로 옮겼다. 코드와 원장은 같은 내용이다. 그 뒤로는 이 폴더에서 돌린다.
- 실행은 사용자가 한다 (11/18 사용자 결정). B는 실행 명령을 주고, 끝났다는 연락을 받으면 결과를 읽어 다음 실험을 정한다. 11/18 스크래치에서 B가 돌리던 RL 학습 선별은 끝난 작업 5개(R0 2016·2017·2019, R-smoothk-0.5 2016·2017)를 `explore/b09/runs/`로 옮기고 멈췄다. 나머지는 사용자가 같은 작업 파일로 이어서 돌린다 (끝난 작업은 건너뛴다).

## 2. 실험 도구 (`explore/b09/`)
실행: `.venv/Scripts/python.exe -I explore/b09/run.py <스크립트> [인자]` (`-I`는 스크립트 폴더를 경로에 넣지 않아 `run.py`가 넣는다)

- 결론: 공식 정책의 작은 MDD(T7 보유 80 100%의 52.2%보다 작음)는 현금 53%에서 나온다. 같은 현금을 두면 공식 정책은 CAGR·MDD 모두 T7 보유 80보다 못하다. 공식 정책은 성능이 가장 좋은 구성이 아니다.
- 참고 (11/20 사용자 질문 "forward test 모델을 이것으로 바꾸면 사전등록 모델보다 낫나", 결과 읽기): 지금 forward test 모델은 사전등록 버퍼 + M8 + M9다 (design_B 5.4절, RL 최종 정책 전까지). 그 10년 값은 −7.7%·MDD 68.7%, 2016~2020 −7.2%·53.6%, 2021~2025 −7.8%·56.4%다. T7 보유 80 + 현금은 백테스트에서 이것과 사전등록 RL 둘 다보다 두 구간 모두 CAGR이 높고 MDD가 작다. 다만 T7·보유 80은 이 기간을 보고 고른 구성이고, 현금 53%는 비교용 값이다. 교체는 PM 결정(DEC)과 deviation_log가 먼저다 (1절). B 제안: 교체 대신 사전등록 모델 옆에 병행 기록.
- 참고 (11/20 사용자 질문 "KPI 판정을 이 모델로 바꾸면 안 되나"): R-15(표본 외 결과를 본 뒤 바꾼 설계는 탐색으로만 보고, KPI는 사전등록 설계)로 안 된다. 바꿔도 G4는 미달이다 (코스피 200 대비 연 −7.5%p, IR −0.65). G5는 RL 대 버퍼 판정이라 해당이 없다. G7 식에 고정 현금을 대면 MDD 감소 47%·CAGR 차 −1.91%p로 0.09%p 차이로 넘지만, 사전등록 M8이 아니고 현금 비중을 사후에 정한 값이다. B 제안: KPI는 사전등록 설계로 판정하고 탐색은 원인 분석(비용 구조)·개선안으로 보고한다. 새 모델은 12/11 홀드아웃 개봉 전에 규칙을 고정해(PM 승인·deviation_log) 사전등록 모델과 함께 평가한다.

## 26. 고정 모델 T7-80-C53 (11/20 사용자 결정: 25절 모델을 홀드아웃 개봉 전에 고정하고 PM에 요청)
- 목적: 탐색으로 찾은 모델 하나를 12/11 홀드아웃 개봉 전에 고정해, 사전등록 모델과 같은 미공개 구간(2026-01 ~ 2026-10 신호일)에서 함께 보고한다. forward test에는 사전등록 기록 옆에 따로 기록한다.
  - KPI 판정은 사전등록 설계 그대로다 (R-15). 이 모델의 결과는 '탐색 모델의 표본 외 확인'으로만 보고한다.
  - PM 승인(DEC)과 deviation_log 기록이 먼저다. 승인 전에는 이 모델로 아무것도 새로 돌리지 않는다.

**규칙 (25절 'T7 보유 80 + 현금'과 같다)**
1. 입력: A 신호의 rank_score·crash_flag, U_t, 업종, M9 경보. 홀드아웃·forward에서는 사전등록 모델과 같은 A 최종 모델 신호와 같은 M9 경보를 쓴다.
2. 순위: 종목별 rank_score를 그 종목의 최근 4개 신호일 평균으로 바꾸고 U_t 안에서 다시 순위를 매긴다 (`turnover.smooth_signals(·, 4)`). 평균에는 그 구간의 신호만 쓴다. 첫 3주는 있는 만큼만 평균하며, 백테스트의 2016년 시작과 같다.
3. 보유: 진입 rank ≤ 80, 청산 rank > 140, 최대 80종목, 같은 비중 (`buffer_rule_weights`). crash_flag·M9 쿨다운 종목은 사지 않고, 들고 있으면 판다.
4. 한도: 종목 10%·업종 30% (사전등록 M8 Step 2·3). 잘린 비중은 현금으로 둔다.
5. 리밸런싱: 첫 신호일부터 2개 신호일마다 한다. 그날 목표 비중에 E = 0.466107을 곱한다 (현금 53.3893% = 공식 RL 5시드의 10년 평균 현금). 사이 주는 실제 보유 비중을 그대로 두고 3·4만 적용한다.
6. 체결·비용: C 엔진, 사전등록 비용·매도세. 현금 100%에서 시작하고, 현금 수익은 0이다.
- 코드: `explore/b09/samecash.py`의 cash 실행이다 (`turnover.run` → `common.buffer_run` 11/20 고친 판, trade_every = 2). 커밋 해시는 고정할 때 적는다.
- 2016~2025 백테스트 (25절, 여러 번 본 구간): 10년 +3.0%·MDD 27.5%, 2016~2020 +2.6%·27.5%, 2021~2025 +3.1%·14.0%, 평균 현금 53.9%, 연 회전율 3.1.

**실행과 보고 (미리 정함)**
- 홀드아웃: 2026년 구간 결과는 개봉 전에 아무도 보지 않는다.
  - 이 PC의 가격 파일에 2026-11-06까지 들어 있다. 그래서 실행 코드는 C 가드 `assert_outcome_dates_allowed`(허용 플래그 + 12/11 이후 실행)를 거치게 한다.
  - B는 2026년 구간을 돌리지 않는다. 개봉 때 C가 사전등록 모델과 같은 엔진·같은 구간으로 한 번 돌린다.
- forward: 승인 다음 신호일부터, 사전등록 기록과 같은 신호로 목표 비중을 따로 기록한다. 기록 위치·형식은 D·PM과 정하고, 마감(DEC-04)은 사전등록 기록과 같다.
- 보고 지표: CAGR, MDD, 코스피 200·코스피 종합 대비 연 초과와 IR, 평균 현금, 연 회전율. 비교는 두 가지로 미리 정한다: (a) CAGR이 사전등록 모델보다 높은가 (b) MDD가 작은가. 기준선 판정은 두지 않는다 (명세 779행 홀드아웃 보고와 같은 성격).
- 홀드아웃에 올리는 탐색 모델은 이것 하나다. 고정한 뒤 바꾸지 않는다. 바꿀 일이 생기면 deviation_log에 적고, 바꾸기 전 규칙의 결과도 같이 보고한다.
- 홀드아웃·forward 실행 코드는 승인 뒤 쓴다. 먼저 2016~2025에서 25절 값을 그대로 재현하는지 대조한다.
