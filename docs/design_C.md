## 1. 공통 시점과 책임

| 시점 | 허용되는 일 | C파트 처리 |
|---|---|---|
| 신호일 `t`의 15:30 이전 | 공시·뉴스의 시각 컷오프 준수 | 신호 입력에 `t` 이후 자료가 섞이지 않았는지 검사한다. |
| `t` 정규장 종가 확정 이후 | A의 신호와 B의 목표 비중 생성 | 신호일을 기록한다. 이 종가로 즉시 체결하지 않는다. |
| 다음 KRX 거래일 `t+1` 종가 | 목표 비중 체결 | C 소유의 공통 체결 함수로 주문 가능 여부와 비용을 계산한다. |
| 체결일부터 다음 체결일 사이 | 일별 수정종가로 평가 | 보유 수량과 현금으로 일간 NAV를 계산한다. 가격 변동에 따른 실제 비중의 변화를 보존한다. |
| `t+1+h` | 라벨 관측 종료 | `h ∈ {1, 5, 20}`의 종목·지수 수익률과 초과수익을 계산한다. |

`t+k`는 달력일이 아니라 `t`로부터 k번째 KRX 거래일이다. 캘린더 원천은
Q-14에서 A파트가 확인한다. M5 백테스트, M4 RL 환경, M7 forward test는
4.3절의 **같은 체결 함수**를 호출한다. 이 규칙을 각 모듈에 따로 구현하지 않는다.

PM PR #2의 `available_at < t 15:30 KST` 시점 처리와 미검증 과거
종목코드 결측·공개 차단은 C가 검토해 승인했다. 회사코드↔종목코드의
시점별 근거와 공개 재개는 후속 계약이다. M5는 원시 `rcept_dt`의
날짜 부분으로 이벤트 적격성을 추정하지 않고, 합의된 시각 기준으로
PM이 만든 M9 경보·쿨다운을 입력받는다.

공통 표기는 다음과 같다. 종목코드는 앞자리 0을 보존하는 6자리 문자열,
날짜는 `YYYY-MM-DD`, 금액은 원(KRW), 수익률과 비중은 소수, 계산은
`float64`다. 성과에는 단순수익률을 사용하고 로그수익률은 변동성 계산에만
사용한다. 현금 이자는 0%다.

## 3. 라벨 설계 — 4.6절, C-02

신호일 `t`와 `U_t`의 종목 `i`마다 `h ∈ {1, 5, 20}`에 대해 다음을 계산한다.

```text
R_i(t,h)      = close_i(t+1+h) / close_i(t+1) − 1
R_BM(t,h)     = BM(t+1+h) / BM(t+1) − 1
ER_i(t,h)     = R_i(t,h) − R_BM(t,h)
y_rank_i(t,h) = U_t 안에서 ER_i(t,h)의 백분위 순위
y_crash_i(t)  = 1 if ER_i(t,20) <= −0.15 else 0
```

`y_rank`는 해당 신호일·기간의 유효한 `U_t` 행에
`rank(pct=True, method="average")`를 적용한다. 같은 초과수익에는 평균
순위를 준다. `y_crash`는 `h=20` 행에만 저장한다. 출력 스키마는
`date`(신호일), `ticker`, `h`, `ret`, `er`, `y_rank`, `y_crash`다.
`ret`은 `R_i(t,h)`, `er`는 `ER_i(t,h)`에 대응한다. 미래 가격은 **라벨과
사후 성과 계산에만** 사용한다.

| 상황 | 라벨 처리 |
|---|---|
| `t+1`에 거래정지 | 해당 종목·신호일 라벨을 만들지 않고 학습·IC 표본에서 제외한다. |
| `t+1+h`에 거래정지 | 거래 재개 첫날 수정종가를 종료 가격으로 사용한다. |
| 기간 중 상장폐지 | 정리매매 마지막 종가를 사용하고, 가격이 없으면 0으로 평가한다. |
| 계산 시점까지 거래 재개 없음 | 라벨을 만들지 않고 누락 건수를 보고한다. |

DEC-28의 재사용 종목코드 `101970`·`036220`은 구회사 폐지 기록을
구회사 상장 구간의 라벨에만 적용한다. 폐지 뒤 가격 공백을 거쳐 나타난
신회사의 라벨에는 그 폐지 기록을 적용하지 않는다.

라벨 누락은 0으로 채우지 않는다. 결측 사유별 건수를 리포트에 남긴다.
신호일·티커·기간의 중복, 유니버스 밖 티커, 비정상 가격과 지수 값은
입력 오류로 처리한다.

### 분할과 홀드아웃 차단 — 4.7절

- Walk-Forward 테스트 신호일은 2016~2025년이다. 폴드 `Y`는
  2011~`Y−3`년 학습, `Y−2`~`Y−1`년 검증, `Y`년 테스트다.
- 구간 경계에서는 명목 `t+1+h`가 **다음 구간의 첫 신호일 이상**인 앞 구간
  신호일을 제거한다. 거래정지로 라벨 확정이 늦어졌다면, 해당 신호일의
  라벨 중 **하나라도 실제 종료일이 다음 구간의 첫 신호일 이상**인 경우
  신호일 전체를 추가로 제거한다. 일부 종목의 미래 수익이 같은 날의
  `y_rank`에도 반영되기 때문이다. 이 규칙은 2026-11-03
  `DEC-09 (3) 변경`으로 확정됐으며 앞선 행 단위 제거 규칙은 폐기됐다.
  공용 함수는
  `src.common.guards.purge_signal_dates(signal_dates, *, trading_days, h,
  next_segment_first_signal, actual_end_dates=None)`이다. `actual_end_dates`에는
  C 라벨 종료일 기록에서 만든 신호일별 최대 실제 종료일을 전달한다.
  A·B·C는 학습→검증, 검증→테스트, 학습 전체→홀드아웃에서 같은
  반환 신호일 집합을 쓴다.
- `src/common/guards.py`는 학습·튜닝 입력의 신호일이
  `2025-12-31`을 넘으면 예외를 낸다.
- `2026-01-01`~`2026-10-31` 신호일의 라벨 생성은
  `--allow-holdout`이 있고 실행일이 `2026-12-11` 이후일 때만 허용한다.
  홀드아웃 평가는 PM의 승인 기록 후 C가 1회 수행한다.
- 홀드아웃을 열기 전에는 그 구간의 라벨·성과를 계산하지 않는다. 2026년
  11월 이후의 forward test는 커밋된 신호의 사후 기록이며 KPI 판정에
  사용하지 않는다.
- 홀드아웃 판정 기간은 **2026년 첫 신호일의 t+1 체결 직전부터
  2026-10-31 이전 마지막 거래일 종가까지**다. PM의 승인 기록과 실행
  시각이 있어야 C가 1회 평가한다.

## 4. 공통 체결·비용 설계 — 4.3·4.8절, C-03

공통 체결 함수는 날짜, 목표 비중, 체결 직전 보유 수량·현금, 수정종가,
전일 종가, `status.is_halted`, 상장폐지 상태, 이벤트 청산 요청, 비용 설정을
입력으로 받는 **순수 함수**로 설계한다. 출력에는 체결 후 보유 수량·현금,
실제 매수·매도 금액, 비용, 미체결 사유와 추후 재시도 대상이 들어간다.
M4와 M7은 동일한 함수를 호출한다. 상·하한가 판정 수익률에는 A의
**수정종가 `close`**를 쓴다. 거래정지는 `status.is_halted`로 판정하며,
DEC-26에 따라 v1의 해당 값은 `volume == 0` 근사다. 실제 정지와 단순
무거래가 섞일 수 있다는 편차를 실행 기록에 남긴다.

기본 M5 실행은 `positions`의 M8 적용 후 목표 비중만 체결한다. v0.3
R-06이 명시한 개인 행동 프록시, G6 기간 비교, G7의 M8·M9 미적용 비교,
G4의 노출 조절 제외 진단에만 각각 정해진 예외를 적용하고, 실행 기록에
예외 종류를 남긴다.

체결 순서는 다음과 같다.

1. 신호일 `t`에 만든 목표 비중이 M8을 거친 결과인지 확인하고 다음
   KRX 거래일 `t+1`의 종가를 체결 가격으로 선택한다.
2. 체결 직전의 실제 보유 비중을 **당일 수정종가와 보유 수량**으로
   계산한다. 목표 비중과의 차이만큼 매수·매도 주문을 만든다.
   `positions` 파일에는 비중이 양수인 종목과 `CASH`만 있으므로 파일에
   없는 종목의 목표 비중은 0(전량 매도)으로 해석한다.
3. `t+1`의 전일 대비 종가 수익률이 `+0.295` 이상인 종목은 매수하지
   않고 해당 금액을 현금으로 둔다. `−0.295` 이하인 종목은 매도하지
   않고 보유한다.
4. 거래정지 종목은 체결하지 않고 마지막 거래일 수정종가로 평가한다.
   체결일에 정지로 줄이지 못한 보유분은 재개 첫날 **최신 목표 비중의
   초과분만 매도**한다. 막힌 매수는 재시도하지 않고, 매도 대금은 다음
   신호일까지 현금으로 둔다. 재개일이 하한가 근접이면 다음 신호일에
   다시 판단한다. 회전율은 원래 체결일 목표로 한 번만 세며, 매도
   비용은 실제 재개일에 기록한다(DEC-25). M9 이벤트 청산이 하한가
   근접으로 실패하면 다음 거래일 종가에 다시 시도한다.
5. 보유 중 상장폐지되면 마지막 정리매매 종가로 청산한다. 그 가격이
   없으면 해당 보유분 가치를 0으로 처리한다.
6. 실제 매매 금액에 아래 비용을 적용하고 보유 수량과 현금을 갱신한다.
   거래량에 따른 수량 제한은 두지 않는다.

같은 `t+1`에 리밸런싱과 M9 청산·쿨다운이 겹치면 **M9가 우선**한다.
그 종목의 목표 비중은 0으로 덮어써 신규 매수를 금지하고 보유분 전량
매도를 시도한다. 거래정지·하한가로 실패하면 미체결 이유와 재시도 상태를
남긴다. `t` 15:30 이후 공시는 `t` 목표 비중에는 없더라도 `t+1` 청산에
반영될 수 있다.

```text
buy_cost  = buy_notional  × (commission_per_side + slippage_per_side)
sell_cost = sell_notional × (sell_tax + commission_per_side + slippage_per_side)

sell_tax             = 0.0020
commission_per_side  = 0.00015
slippage_per_side    = 0.0010
stress_multiplier    = 2.0
```

2배 비용 시나리오는 **세 비용률 모두**에 `stress_multiplier`를 곱한다.
비용 0인 실행은 EW 일치 검증과 비용 전후 비교의 명시적 예외다. 기본
백테스트는 비용을 차감한다. M9 청산 대금은 다음 신호일까지 현금으로
유지한다.

### 일별 회계와 NAV

```text
NAV_d = Σ_i(보유 수량_i,d × 수정종가_i,d) + 현금_d
```

체결하지 않는 거래일에도 당일 수정종가로 NAV를 평가한다. 목표 비중은
체결을 위한 명령이고, 실제 보유 비중은 가격 변동·미체결·비용 때문에
달라질 수 있다. 현금의 일간 수익률은 0이다. 연도 경계에서 포트폴리오를
초기화하지 않고 보유를 이어가며 다음 폴드의 모델로 바꾼다.
일별 기록에는 NAV, 현금, 보유 수량, 실제 비중, 매매 금액, 비용,
미체결 사유를 남겨 결과를 재계산할 수 있게 한다.

### M4·M5·M7 공용 구간 실행 함수

공개 인터페이스는 B-01 PR #4의 `src/portfolio/interfaces.py`에 맞춰
`src.backtest.engine.ExecutionEngine`의
`initial_state()`와
`run_period(state, targets, signal_date, next_signal_date) -> PeriodResult`로
둔다. `initial_state()`는 현금 100%, NAV 1의 상태를 만든다.
엔진 생성 시 일별 수정종가·전일 수정종가·거래정지·상장폐지,
M9 청산·쿨다운, 비용 설정, 일별 KOSPI200 종가를 전달한다.
`targets`는 M8 적용 후 종목 비중이며 빠진 종목은 목표 0이다.
일별 처리 순서는 **M9 우선순위 적용 →
리밸런싱/청산 체결 → 체결 후 NAV 평가 → 다음 거래일로 이동**이다.
M4 RL 환경과 버퍼 규칙 백테스트가 이 함수를 함께 호출한다.

`PeriodResult`는 `nav_start`(첫 체결일의 체결 직전 NAV),
`nav_end`(다음 체결일의 체결 직전 NAV), 구간 내
**체결 후 일별 NAV의 최댓값** `nav_max`,
`r_net = nav_end / nav_start - 1`,
`r_bm = BM(다음 체결일) / BM(첫 체결일) - 1`, 첫 체결일의 목표 대비
체결 직전 회전율 `turnover`, 다음 호출용 `state`(보유 수량·현금·M9
미체결 상태), 다음 신호일 종가 기준 `weights_obs`와 `cash_obs`를 돌려준다.
일별 전·후 NAV 및 체결 로그는 엔진의 별도 기록에 남긴다.
다음 체결일 종가의 리밸런싱은 **다음 호출**에서 수행한다. 따라서 해당
날짜의 `nav_end`는 체결 직전이며, 중간 날짜의 M9 청산은 포함된다.
주간 초과수익 `a_k`는 `r_net - r_bm`과 같은 경계로 계산한다.
동일 입력의 버퍼·RL 실행은 체결·비용·NAV가 같아야 한다.

### Forward test의 실제 보유 재생 — C-04

`ExecutionEngine.run_to_signal_close(state, targets, signal_date,
next_signal_date) -> SignalCloseResult`는 위와 **같은 일별 체결 로직**을
사용하되 다음 신호일 `t′` 종가에서 멈춘다. `t′+1` 가격을 요구하지
않으며, 결과의 `state.asof_date`, `weights_obs`, `cash_obs`는 모두
`t′` 종가 기준이다. `run_period`의 기존 `t′+1` 체결 직전 NAV 경계와
반환 계약은 그대로 둔다.

11/20 첫 비중 기록은 현금 100%에서 시작한다. 이후 D가 `ft-{날짜}`
태그에서 기록된 목표 비중을 순서대로 읽고, B가 같은 엔진에 전달해
마지막 신호일 종가의 **실제 보유 종목**을 버퍼 규칙의 지난 보유로
사용한다. 목표 비중 파일의 종목을 그대로 지난 보유로 간주하지 않는다.
미체결·M9 청산·상장폐지·비용이 모두 반영된 `state`를 다음 호출에
넘긴다. C-04 사후 성과도 이 재생 경로를 공유한다. 가격·상태·경보 입력은
각 기록 시점에 공개된 자료까지만 사용하고, 종료 신호일 `t′` 뒤 가격이
필요하면 호출을 거부한다.

뉴스 피처 검증에서는 `news_daily.available_at < t 15:30 KST`를
확인하고, `t−5~t−1`과 `t−65~t−6` 창의 이용 가능한 거래일을
검사한다. 확인된 0건과 수집 실패·종목 매핑 미확인 결측을 구분한다.
뉴스 피처 기여도 비교는 같은 평가 기간·표본에서 모델을 다시 학습해
수행한다. 공용 `news_daily` 스키마와 결측 규칙이 병합되면 실행 검사를
연결한다.

약 1,900만 RL 스텝을 고려해 구간 함수는 배열 기반 계산을 우선하고
호출당 1 ms 이하를 목표로 벤치마크한다. 먼저 정확성을 테스트하고
실측한 병목만 최적화한다.

## 5. 공통 지표 함수 — 6.6절, C-03

모든 KPI, 보고서와 대시보드는 M5의 **같은 지표 함수** 결과만 사용한다.
함수는 동일한 판정 기간의 포트폴리오·BM을 날짜로 맞추고, 결측을
임의로 0으로 대체하지 않는다.

| 지표 | 계산 규칙 |
|---|---|
| CAGR | `(NAV_end / NAV_start) ** (252 / 거래일 수) - 1`; 거래일 수는 첫 체결일과 최종 평가일 사이 일간 수익률의 개수 (`일별 평가 행 수 - 1`) |
| 연 초과수익 | 같은 기간의 `CAGR(포트폴리오) - CAGR(BM)` |
| 주간 초과수익 `a_k` | k번째 **체결 직전 NAV**부터 다음 체결일의 **체결 직전 NAV**까지 포트폴리오 단순수익률에서 같은 기간 BM 단순수익률 차감. 첫 체결일 비용은 그 주에 포함한다. |
| IR | `mean(a) / std(a, ddof=1) * sqrt(52)` |
| MDD | 일별 NAV에서 `max(1 - NAV_d / 이전~당일 최고 NAV)`; 양수 |
| 1회 회전율 | `0.5 * sum(abs(목표 비중 - 체결 직전 비중))`; 현금 제외 |
| 연 회전율 | 판정 기간의 회전율 합 / 연수 |
| rank IC | 신호일별 `Spearman(rank_score, ER(t,20))`의 평균; t값은 상수항 OLS, `cov_type="HAC"`, `maxlags=4` |
| ROC-AUC | 판정 기간의 모든 종목·신호일 쌍에 대해 `roc_auc_score` |
| lift@10% | `(crash_flag=1 집단의 실제 급락 비율) / (전체 집단의 실제 급락 비율)` |
| 하방 포착률 | 스트레스 구간 포트폴리오 수익률 / 같은 구간 BM 수익률 |
| 반등 포착률 | 일간 수익률 `d−1→d`에 `d−1` 종가 기준 `regime_mc=1`을 맞춘 거래일들의 포트폴리오 누적수익률 / 같은 날들의 BM 누적수익률 |

연율화 기준은 일간 252, 주간 52다. 분모가 0이거나 표본이 부족해
지표를 정의할 수 없으면 성공·실패를 임의로 판정하지 않고 이유와 함께
미산출 상태로 보고한다. `rank IC`와 `ROC-AUC`는 유효 라벨이 있는
종목·신호일만 사용하며 누락 건수를 함께 기록한다. 평가 기간은
Walk-Forward의 2016년 첫 신호일 체결부터 2025년 마지막 거래일
종가까지다.

B-01의 `IRFunction`은 `float`를 반환하고 검증 콜백은 비유한 IR을
체크포인트 선택에서 제외한다. C의 보고서용 `information_ratio`는
미산출 시 `None`을 반환하며, B 연결에는 `validation_ir` 어댑터가
`NaN`을 반환한다. 정의 가능한 경우 두 함수의 값은 같다.

체결일의 일별 장부에는 **체결 직전·직후 NAV를 둘 다** 기록한다.
일간 MDD는 체결 후 NAV 시계열로 계산한다. 2025년 마지막 신호일 뒤
다음 체결일이 없는 잔여 거래일은 일간 NAV·CAGR·MDD에는 포함하되,
완료된 두 체결일이 없어 `a_k`와 IR의 주간 표본에서는 제외한다.
반등 포착률에 쓰는 일별 `regime_mc`는 B-01의
`market_state_table(..., mode="no_exposure")` 결과를 M8과 공유한다.
해당 일간 수익률이 국면 판정에 섞이지 않도록 전일 값을 정렬해 사용한다.

### 개인 행동 프록시와 G2 — C-04 설계

신호일 `t`마다 `U_t`에서 DEC-22의 거래대금 비율
`mean(V,t-4~t) / mean(V,t-64~t-5)` 상위 30종목을 코호트로 뽑는다.
각 코호트는 `t+1` 종가에 당시 NAV의
**1/4**을 종목별 동일가중으로 매수한다. 현금이 부족하면 가용 현금만
사용한다. 20거래일 후 종가에 청산하며, 공통 M5 체결·비용 규칙을
적용한다. 게이트 적용 버전은 같은 코호트에서 `crash_flag=1`을 제외하고
나머지 종목에 동일가중 투자한다. M8·M9는 적용하지 않는 R-06 예외다.

`crash_flag=1`이 있는 신호일마다
`d_t = mean(ER(t,20) | flagged) - mean(ER(t,20) | unflagged)`를 만든다.
`d_t` 평균의 t값은 rank IC와 같은 상수항 OLS·HAC(`maxlags=4`)로
계산한다. DEC-22 대체 정의와 누락 표본을 실행 설정·리포트에 남긴다.
코호트 운용과 `d_t` 계산은 C 홀드아웃 가드를 호출하며, 플래그가 없는
신호일과 한쪽 집단의 유효 라벨이 없어 미산출된 신호일을 따로 센다.

코호트 선정, `d_t`, 운용 NAV와 G2 판정은
`src.backtest.retail_proxy`에 분리한다.
분모 60거래일에 0 또는 65거래일 중 결측이 있으면 해당 종목의
정렬 점수를 만들지 않고 사유별 건수를 기록한다. `d_t`는 유효한
`crash_flag`와 h=20 초과수익이 모두 있는 쌍만 쓰며, 한쪽 집단이
비면 그 신호일은 미산출로 센다. `simulate_retail_proxy`는 코호트별
보유 수량을 따로 추적하고, 공통 C `execute_orders`·`trade_cost`와
엔진의 정지일 평가 가격을 사용한다. 20거래일 뒤 매도가 정지·하한가로
막히면 다음 거래일에 다시 시도하고, 막힌 매수는 재시도하지 않는다.
이 청산 재시도 해석은 실제 데이터 연결 전에 PM·B와 확인한다.
G2 판정은 게이트 전후 동일한 NAV 날짜, 상대 MDD 축소, CAGR 비열화,
`d_t` HAC t값이 모두 정의됐을 때만 성공/실패를 낸다.

### Forward test 사후 성과 — C-04 설계

D가 신호일에 먼저 커밋한 `signals/{t}.parquet`·`positions/{t}.parquet`와
`forward_log.csv`를 입력으로 받는 사후 함수가 **t+21거래일 이후**
(`label_ready_date` 이후)에
M5의 라벨·체결·NAV·지표 함수를 호출한다. 확정 전까지
`mean_er_top20`, `mean_er_flagged`, `portfolio_return`, `bm_return`은
비워 둔다. 사후 결과에는 `signal_date`, 원래 `commit_hash`,
`signal_source`, `has_positions`를 함께 보존하고, 원래 신호·비중을
다시 계산하거나 수정하지 않는다. 2026년 홀드아웃 신호일은 개봉 조건을
통과하기 전에는 이 경로로도 성과를 계산하지 않는다.
포트폴리오 수익의 종료 NAV는 `t+21` 종가의 **새 리밸런싱 체결 직전**
값이다. 그날 체결할 직전 신호의 목표 비중과 비용은 이 기록의
20거래일 성과에 넣지 않는다.

`src.backtest.forward_outcomes.evaluate_forward_record`는 KRX 달력으로
`label_ready_date`를 다시 검증하고 종료일 15:30 KST 전 실행을 거부한다.
원본 신호의 상위 20종목과 급락 플래그 종목에 h=20 라벨을 연결하며,
필요한 라벨이 결측이면 해당 평균은 미산출로 둔다. positions가 없는
기록은 포트폴리오·BM 수익을 비워 둔다. positions가 있는 기록은
`ft-{날짜}` 태그에 보존된 모든 목표 비중을 현금 100%부터 공통 엔진으로
재생한다. 해당 기록의 `t+1` 체결 직전 NAV부터 `t+21` 종가 NAV까지,
그 사이 실제 주간 리밸런싱을 포함해 단순수익률을 구한다. BM도 같은
두 종가를 쓴다. 평가 대상 기록의 목표 비중이 없으면 중단한다. 중간 주에
커밋된 목표 비중이 없으면 새 리밸런싱 없이 직전 실제 보유를 유지한다.
M9 적용 실행은 PM의 `AlertBook.engine_alerts(첫 기록일, 종료일)`을
`engine_alerts` 인자로 넘겨 B와 같은 거래일별 쿨다운·청산 일정을
엔진에 붙인다. 이때 원본 엔진을 변경하지 않고 별도 실행 인스턴스를
사용한다.

## 7. 연결 전 확인할 결정

아래는 v0.3의 수치나 정책을 변경하자는 뜻이 아니다. 구현 시 서로 다른
회계 결과가 나오지 않도록, 소유자 간 입력·출력 경계를 확인해야 한다.

1. **비용을 포함한 목표 비중 체결:** 체결 직전 NAV로 목표 금액을 정하면
   비용 차감 후 목표 비중과 실제 비중에 차이가 난다. DEC-18에 따라
   매도를 먼저 실행하고, 매수 금액과 비용이 가용 현금을 초과하면
   모든 매수를 동일한 비율로 줄인다. 공통 구간 함수에 이 규칙을 적용한다.
2. **거래정지·상장폐지 가격 공백:** DEC-25에 따라 정지 중에는 마지막
   거래일 수정종가로 일별 NAV를 평가한다. 상장 전·폐지 후 가격 결측은
   허용하되 보유·목표 종목에 필요한 평가 가격이 없으면 오류로 처리한다.
   DEC-28의 재사용 종목코드 두 건은 구회사 폐지 후 가격 공백과 신회사
   첫 가격으로 상장 구간을 나누며, 명시적 구간 형식은 v2에서 결정한다.
3. **G0 검사 시점:** M8 목표 비중에 대한 검사와 미체결 후 실제 보유
   비중의 검사는 구분한다. G0의 판정 대상은 v0.3대로 M8을 통과한
   **목표 비중**으로 하고, 미체결로 생긴 차이는 별도 기록한다.
4. **공통 함수 연결:** D의 `src/common/io.py`가 확정되면 파일 접근은
   그 함수로만 통일하고, B의 RL 환경 및 D의 forward test가 C 체결
   함수를 직접 호출하는 경계를 함께 검토한다.
5. **G0 업종 한도 검증 입력:** 9.3절의 `sector.parquet` 소비자는 B만으로
   적혀 있지만 6.6절은 C의 G0 자동 검사를 요구한다. C가 해당 파일을
   공통 I/O로 읽고 B-01의 `sectors_at`과 같은 t일 유효행·'미분류'
   규칙을 사용한다는 안으로 정리한다. 9.3절 소비자에 C를 추가하는
   변경은 PM의 기록과 B-01 upstream 병합 후 진행한다.
6. **거래 재개일의 기존 목표 적용:** 체결일에 거래정지로 줄이지 못한
   보유분만 재개 첫날 종가에 최근 목표 비중을 넘는 만큼 매도한다.
   정지로 사지 못한 매수는 다시 시도하지 않는다. 재개일 하한가면

   우선한다. M9 청산·쿨다운은 일반 목표보다 우선하며 M9 미체결
   청산은 매일 재시도한다. DEC-25로 PM이 확정했다.
