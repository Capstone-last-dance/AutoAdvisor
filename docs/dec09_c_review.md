# DEC-09 C파트 재검토안 (2026-11-02)

대상: PM PR #2 헤드 `49e7fdc`와 `decisions.md`의 DEC-09, D PR #6 병합본.
PM이 결정하고 D가 동의했으며 C의 검토가 남아 있다. 이 문서는 C의
평가 입력 검토 결과다. PR #2의 현재 코드는 D 공용 스키마와 A의
`tickers`가 준비되면 공개 저장을 허용하므로 아래 이견을 해소해야 한다.

## C가 수용하는 시점 규칙

1. `rcept_dt`는 **실제 접수 시각**이다. 원천이 날짜만 주면 결측으로 둔다.
2. `available_at`은 별도의 **이용 가능 시각**이다. 날짜만 있는 OpenDART
   목록은 원본 접수 날짜와 접수번호 앞 8자리 날짜 중 늦은 날의
   `23:59:59 KST`를 사용한다. 실제 접수 시각을 알 때도
   `available_at >= rcept_dt`를 지킨다.
3. 신호일 `t`의 정보 선택은 시간대 포함 시각으로
   `available_at < t 15:30 KST`를 적용한다. 같은 시각은 제외한다.
   `.date()` 비교, 실행 시각을 컷오프로 쓰는 방식은 허용하지 않는다.
4. 회사코드와 종목코드의 **당시 유효 기간 및 관측 시점 근거**가 없으면
   `ticker`는 결측으로 둔다. 최근 수집의 `stock_code`를 과거 공시에
   소급하지 않는다. 결측 공시는 종목별 피처와 M9 종목 경보에서 제외하고
   제외 건수를 보고한다.
5. 날짜만 있는 legacy 6열 결과를 실제 접수 시각으로 해석하지 않는다.

PR #2의 `filter_disclosures_before` 경계·시간대 테스트와 공용 I/O 사용은
위 규칙에 부합한다. 다만 새 코드의 상장 기간 검사만으로는
**그 접수일에 해당 회사(`corp_code`)가 그 종목코드를 사용했다는 사실**이
증명되지 않는다. 2026년에 관측한 `stock_code`가 2015년에도 상장돼
있었다는 것과 2015년 공시의 회사에 연결됐다는 것은 서로 다른 조건이다.
수집 시점이 다른 코드 변경 사례를 `tickers`가 함께 있는 조건에서
검증하고, 회사코드↔종목코드의 시점별 근거가 없다면 종목별 피처와
M9 입력에 사용하지 않는 규칙이 필요하다. **현재 PR의 C 승인은 보류한다.**

## C 라벨 purge 제안

기존 명목 종료일 `t+1+h`가 다음 구간 첫 신호일 이상이면 앞 구간의
신호일을 제거한다. 거래정지로 종료 가격이 늦게 확정된 경우,
**그 신호일의 어떤 라벨이라도 실제 종료일이 다음 구간 첫 신호일
이상이면 신호일 전체를 제거한다.** `y_rank`가 같은 신호일의 여러
종목 수익을 함께 쓰기 때문이다. C의 `end_dates`에서 신호일별 최대
`actual_end`를 만들어 `purge_signal_dates(..., actual_end_dates=...)`에
전달하고 A·B·C가 같은 반환 신호일 집합을 사용한다. PM이 기록한
DEC-09는 지연된 **해당 행만** 제거한다. C의 `build_labels`가 제거 전
전체 종목의 수익으로 `y_rank`를 계산하므로, 행만 제거하면 남은 행의
순위에 다음 구간에서 확정된 수익이 남는다. 행 단위 purge를 유지하려면
그 후 각 `(date, h)`의 `y_rank`를 다시 계산하고, A·B·C가 같은 표본을
사용한다는 절차를 결정·테스트해야 한다.

## PM·D 공동 확정이 필요한 공개 계약

| 항목 | 필요한 결정 |
|---|---|
| `disclosures.parquet` | PM이 공개 9열을 기록했다. `rcept_dt` nullable, `available_at` non-null KST, `ticker` nullable은 C도 수용한다. |
| D `io.py` | 현재 6열 검증기는 위 규칙을 받지 않는다. 결정된 열·자료형으로 `read_table`·`validate`·`write_table`을 함께 갱신한다. |
| `alerts.parquet`와 M9 | 실제 시각이 없는 공시의 `rcept_dt` 결측, 별도 `available_at`, 경보 발생일·다음 거래일 청산·쿨다운의 기준을 같은 시점 규칙으로 정한다. |
| 종목 매핑 | 상장 기간 검사와 회사코드↔종목코드의 당시 연결 근거를 구분한다. 연결 근거를 공급하거나, 없는 행은 종목별 피처·M9 입력에서 제외한다. 변경된 코드를 나중에 관측한 합성 사례를 추가한다. |
| 라벨 purge | DEC-09의 행 단위 제거와 `y_rank` 계산 순서를 맞춘다. 신호일 전체 제거 또는 제거 후 순위 재계산을 공동 확정한다. |
| 통합 테스트 | archive → build → D 공용 I/O → 신호 컷오프 → 피처/M9까지 한 흐름에서 당일 제외·다음 거래일 포함, 매핑 결측, 공개 스키마를 검증한다. |

이견을 DEC-09에 반영하고 통합 테스트가 통과할 때까지 PR #2를 C의
평가 입력으로 승인하지 않는다.
